# 缺陷检查记录 · 2026-10-30

本次检查发现并修复了以下问题。此前已有的 26 项单元测试没有覆盖这些边界。

| 问题 | 原有表现 | 修复方式 |
| --- | --- | --- |
| 遥测时间解析 | 遥测没有 `event.timestamp` 而使用 OTLP 纳秒时间字段时，时间值被误当成超限数值过滤，记录丢失，TPS 无法显示。 | 分开处理 Token 数值与纳秒时间，并支持 `timeUnixNano` 和 `observedTimeUnixNano`。 |
| 乱序请求计时 | 后一次完成事件先到达时，可能使用前一次请求的起点；后续事件到达后也不纠正。复现中两次实际耗时均为 2 秒的请求显示成 10 秒和未知。 | 新边界到达后重新检查受影响的请求区间，纠正已有配对，并防止复用起点。 |
| 最近实测 TPS 消失 | 最近 40 条记录都缺少起始计时时，之前成功测量的 TPS 也会从“最近实测”中消失。 | 最近记录列表和最近有效计时分开查询，保留可核实的历史测量。 |
| 异常或移动中的日志 | 非对象 JSON 记录会抛出异常；会话归档移动、单个文件不可读也会中止整轮扫描，启动时甚至无法运行服务。 | 校验记录结构，逐文件处理异常；单个文件不可读时继续扫描其余记录并报告状态。 |
| 扫描阻塞统计接口 | 读取和解析日志期间一直持有统计数据库锁，大文件会拖慢界面刷新和 MCP 调用。 | 文件读取与 JSON 解析移到数据库锁之外，数据库操作仍按锁串行执行。 |
| 本地页面刷新卡住 | 服务不返回响应时，页面没有请求超时，刷新按钮和自动更新可能一直处于等待状态。 | 增加 7 秒超时，超时后释放刷新状态并自动退避重试。 |

验证包括 33 项 Python 测试、2 项基于真实界面脚本的刷新恢复测试，以及虚构数据下的本地 HTTP 服务与 stdio MCP 端到端测试。还保留了对 Token 去重、缓存与推理统计、日期范围、思考强度、费用按模型计算和合计的已有验证。

这份记录描述源码审查阶段的结果；修复包含在 1.4.1 中。部署时需另行同步已安装副本，并备份和保留历史数据库。

这些检查不能证明不存在其他缺陷。TPS 仍依赖完整的 Codex 遥测；缺失的原始计时无法从 Token 数量中还原。第三方 MCP 客户端的具体图形界面也未逐一验证。
